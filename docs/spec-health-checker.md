# Pod Health Checker

**Module:** `packages/admin/evolve_admin/health.py`
**Status:** Active

---

## Purpose

The health checker is a self-contained pod scanner that maps every important file location in an Evolve install, verifies permissions, and checks service state. It runs in three contexts:

| Context | How | Fixes |
|---|---|---|
| Setup wizard (end of `--fresh`) | `run_health_check()` → y/n prompt → `apply_all_fixes()` | Applied directly; wizard runs as root |
| Admin UI → Maintenance → Pod Health | `GET /api/pod-health` + `POST /api/pod-health/fix` | Applied via evolve sudoers grants (no root required) |

The scanner is always read-only. Fixes are a separate, explicit step.

---

## What it checks

Checks are run in order and grouped into categories:

| Category | Checks |
|---|---|
| `network` | `network.json` exists, parses cleanly, has a members list |
| `users` | macOS `evolve` user exists; each bot user account exists (`dscl`) |
| `oc_config` | `~/.openclaw/openclaw.json` for each bot — exists, valid JSON, readable (tries direct read, falls back to `sudo -u {bot}`) |
| `plugin` | `dist/` directory installed in bot's OC plugin path; owned by `root` (security requirement — prevents bot from modifying its own plugin) |
| `shared_dir` | `/Users/Shared/evolve/` mode=`1777`; expected subdirs present |
| `turns_dirs` | Per-bot `{shared}/{bot}/turns/` mode=`1777` (sticky world-writable) |
| `launchd` | All expected plists present in `/Library/LaunchDaemons/`; services loaded (`launchctl list`) |
| `gateways` | HTTP probe each gateway at `http://127.0.0.1:{port}/evolve/status`; admin UI at port 5050 |

### Status levels

- **PASS** — check met
- **WARN** — degraded but not broken (e.g. missing optional subdir, admin UI down)
- **FAIL** — something is broken and needs fixing

The report's `ok` property is `True` when there are zero FAILs (warnings are acceptable for normal operation).

## Fix execution

Each `CheckResult` carries two fix fields:

```python
fix_cmd: str | None   # human-readable description (display only)
fix_args: dict | None # structured descriptor for apply_all_fixes()
```

`fix_args` actions:

| Action | Effect |
|---|---|
| `chmod` | `sudo chmod {mode} {path}` |
| `mkdir_chmod` | `sudo mkdir -p {path} && sudo chmod {mode} {path}` |
| `launchctl_kickstart` | `sudo launchctl kickstart -k system/{label}` |
| `launchctl_bootstrap` | `sudo launchctl bootstrap system /Library/LaunchDaemons/{label}.plist` |
| `setup_shared` | Calls `deploy_shared_dir()` directly (handles full shared dir repair) |
| `deploy_bot` / `deploy_all` | Refused by `_execute_fix` — must route through the deploy flow |

`apply_all_fixes(report, dry_run=False)` iterates all non-passing checks with `fix_args` set and calls `_execute_fix()` for each. Returns a list of `FixResult(name, ok, message)`.

### Execution context requirements

The web server runs as the `evolve` user. The sudoers grants in `/etc/sudoers.d/evolve` (generated by `evolve-admin setup evolve-user`) cover:

- `sudo chmod * /Users/Shared/evolve/*` — turns dir mode and other shared subdir repairs
- `sudo chmod 1777 /Users/Shared/evolve` — root dir mode
- `sudo mkdir -p /Users/Shared/evolve/*` — missing subdirs
- `sudo launchctl kickstart -k system/ai.openclaw.*` — gateway restarts
- `sudo launchctl bootstrap system /Library/LaunchDaemons/ai.openclaw.evolve.*.plist` — service loading

The wizard runs as root via `sudo evolve-admin setup --fresh`, so it can apply every fix class including deploy actions.

## Pod manifest

After every successful scan (i.e. `network.json` loaded cleanly), the checker writes:

```
/Users/Shared/evolve/pod-manifest.json
```

This is a stable, machine-readable record of where every file lives in the current install. Other scripts read it instead of re-walking the filesystem on every run.

### Schema

```json
{
  "scanned_at": "2026-04-12T14:30:00Z",
  "network_id": "my-pod",
  "shared_dir": "/Users/Shared/evolve",
  "summary": { "pass": 24, "warn": 0, "fail": 0, "ok": true },
  "bots": {
    "admin-bot": {
      "oc_dir":        "/Users/admin-bot/.openclaw",
      "oc_json":       "/Users/admin-bot/.openclaw/openclaw.json",
      "plugin_dist":   "/Users/admin-bot/.openclaw/plugins/evolve-plugin/dist",
      "plugin_owner":  "root",
      "turns_dir":     "/Users/Shared/evolve/admin-bot/turns",
      "turns_mode":    "1777",
      "gateway_port":  3001,
      "gateway_live":  true,
      "launchd_gateway": "ai.openclaw.admin-bot-gateway"
    }
  },
  "launchd": {
    "expected_count": 18,
    "expected_labels": ["ai.evolve.evolve.admin-ui", "ai.openclaw.evolve.analyze.evolve", "..."]
  }
}
```

### Reading the manifest from other scripts

```python
from evolve_admin.health import read_manifest

m = read_manifest()
if m:
    oc_json_path = m["bots"]["admin-bot"]["oc_json"]
    turns_dir    = m["bots"]["admin-bot"]["turns_dir"]
```

The manifest is written atomically (write to `/tmp` + copy). If the write fails (e.g. permission denied on shared dir), it silently skips — the manifest is best-effort and never causes a scan to fail.

The manifest reflects the state at scan time. Treat it as a cache: valid until the next scan. Do not use it as the sole source of truth for security-sensitive decisions.

## Admin UI

**Location:** Maintenance → Pod Health tab

- **Scan Now** button — calls `GET /api/pod-health`, renders results grouped by category
- **Fix Issues** button — calls `POST /api/pod-health/fix` (all fixable issues), re-renders
- Per-row **Fix** button — calls `POST /api/pod-health/fix` with `{"names": ["<check-name>"]}` for targeted single-issue repair
- **Overview page** — "Pod Health" stat in the sys-loop bar; red banner appears when FAILs are detected, deeplinks to Maintenance → Pod Health

The tab loads on activation (switching to it triggers `loadPodHealth()`). It does not auto-load on page open — health scans touch the filesystem and probe network ports, so they're intentionally on-demand.

## API

### `GET /api/pod-health`

Runs a full scan. Returns `HealthReport.as_dict()`:

```json
{
  "network_id": "my-pod",
  "shared_dir": "/Users/Shared/evolve",
  "summary": { "pass": 24, "warn": 0, "fail": 0, "ok": true },
  "checks": [
    {
      "status": "PASS",
      "category": "shared_dir",
      "name": "subdir:metrics",
      "detail": "/Users/Shared/evolve/metrics exists",
      "fix_cmd": null,
      "fix_args": null
    },
    ...
  ]
}
```

### `POST /api/pod-health/fix`

Apply fixes. Body (all fields optional):

```json
{
  "names":  ["shared_dir:mode", "subdir:metrics"],  // omit for all fixable
  "dryRun": false
}
```

Response:

```json
{
  "ok": true,
  "fixes": [
    { "name": "shared_dir:mode", "ok": true, "message": "chmod 1777 /Users/Shared/evolve" }
  ],
  "health": { ... }  // updated HealthReport.as_dict() — saves a second round-trip
}
```

Exit codes (CLI): `0` = pass/warn only, `2` = at least one FAIL.

## CLI

```bash
evolve-admin health            # human-readable, show only issues
evolve-admin health -v         # show passing checks too
evolve-admin health --fix      # apply all fixable issues (uses sudo as needed)
evolve-admin health --json     # machine-readable JSON output
```

## Known permission invariants

These are the permission rules the checker enforces. They encode hard-won lessons from past bugs:

| Path | Mode | Owner | Why |
|---|---|---|---|
| `/Users/Shared/evolve/` | `1777` | `evolve:wheel` | Sticky: each bot user creates its own subdir without root access |
| `/Users/{bot}/turns/` | `1777` | `evolve:wheel` | Sticky: each bot writes only its own turns; prevents cross-bot deletion |
| `~/.openclaw/plugins/evolve-plugin/dist/` | any | `root` | Root ownership prevents a bot from modifying its own plugin code |
