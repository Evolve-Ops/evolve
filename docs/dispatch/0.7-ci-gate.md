# 0.7 — CI gates the full test suite · **Tier: Sonnet**

## Context
`.github/workflows/ci.yml` runs only 5 narrow invariant tests (+ `tsc`, gitleaks).
The real ~12,449-test admin+analyzer suite gates **nothing** at the merge boundary,
and the suite has accepted *baseline failures* on clean `main`. Goal: make the full
suite a required check **without** being blocked by the known-failing tests — so any
NEW failure breaks the build while the existing debt is quarantined and visible.

## Task
1. Add a CI job (or two — one per package) that runs the full suite:
   - `cd packages/analyzer && pip install -e . && python -m pytest`
   - `cd packages/admin && pip install -e . && python -m pytest`
   (Clean checkout — the worktree editable-install shadow does NOT apply in CI.)
2. Introduce a **checked-in quarantine list** of currently-failing test node-ids
   (e.g. `ci-quarantine.txt`, one nodeid per line, each with a trailing `# reason`
   comment). Wire pytest to deselect exactly those (a `--deselect`-from-file step or a
   small conftest hook). The job must be **blocking** (fails the build) on anything
   outside the quarantine.
3. Populate the quarantine by running the full suite once and capturing every current
   failure. Confirmed baseline failures to include up front:
   - `packages/admin/tests/test_repo_puller.py::test_pip_install_grant_present_in_evolve_sudoers`
   - `packages/admin/tests/test_repo_puller.py::test_sudoers_self_refresh_grants_present_in_evolve_sudoers`
   (plus any others the run surfaces — the review saw ~12 in one subset).

## Acceptance criteria / proof artifact
- CI runs the full suite and is **red** if you add a throwaway `assert False` test
  (demonstrate, then remove).
- `ci-quarantine.txt` is checked in, every entry has a reason, and a comment block at
  its top says "shrink this — each line is a real failing test."
- CI is **green** on current `main` (because exactly the baseline failures are quarantined).

## Guardrails
- **Do NOT fix the two sudoers failures by editing sudoers or code.** Whether to add a
  sudo grant vs. update a stale test is a security decision owned by the quarterback —
  just quarantine them with `# roadmap 0.7-followup: sudoers grant decision`.
- **Do NOT** make the job non-blocking or `continue-on-error` — that defeats the point.
- **Do NOT** sprinkle `@pytest.mark.skip` inline on individual tests — keep the debt in
  the one central list so it's countable and shrinking.

## Verify
Push to a branch; confirm the new job runs, is green, and goes red on an injected failure.
