# 3.3 — Extend the browser smoke suite for critical flows + theme parity · **Tier: Sonnet**

## Context (corrected 2026-06-09)
The diligence review claimed "zero UI tests" — that was a **false negative**: it
searched for `*.spec.js`/`*.test.js` and missed the Python **pytest-playwright**
suite that already exists at `tests/browser/`. There IS a mature harness:
- `tests/browser/conftest.py` — session-scoped `admin_server` fixture that boots the
  Flask server in a subprocess against a throwaway `network.json`.
- `tests/browser/fixtures/network.json` — the fixture pod.
- `tests/browser/test_smoke.py` (index load, no-console-errors, SPA nav, core API
  endpoints, static assets, PWA manifest shape) + `test_bot_config_ux.py`,
  `test_cost_levers.py`, `test_pwa_alert_messages.py`.
- CI: `.github/workflows/browser-smoke.yml` runs it across chromium/webkit/firefox.

So this is **extend an existing harness**, not greenfield. The gap is coverage of a
few critical flows — most importantly **theme light/dark parity**, which is NOT
currently tested and is the silent-break class the style-guide explicitly warns about.

## Task
Add tests under `tests/browser/`, following the existing patterns (the `page` +
`admin_server` fixtures, `page.evaluate(...)`, the assertion style in `test_smoke.py`):

1. **Theme parity (highest value — currently uncovered).** Toggle the sidebar theme
   button; assert `data-theme` flips light↔dark, that key surfaces actually restyle
   (e.g. computed background changes), and that neither theme produces console errors.
   This test must FAIL if light theme silently regresses.
2. **Improve / Proposals page** renders its list (or a clean empty-state) — add only if
   `test_smoke.py` doesn't already cover that route.
3. **Alerts / Health page** renders — same "only if not already covered" check.
4. (If cheap against the fixture) a bot-detail view interaction beyond what
   `test_bot_config_ux.py` covers.

**First step: read `test_smoke.py` and the other three files and list what's already
covered**, so you only add genuine gaps. Don't duplicate.

## Acceptance criteria / proof artifact
- `python -m pytest tests/browser/ --browser chromium` passes locally including the new tests.
- The theme-parity test fails if you force light theme to break (demonstrate, then fix).
- New tests run green across the existing CI matrix (chromium/webkit/firefox) — they fire
  automatically because they live under `tests/browser/` (see the workflow `paths:`).

## Guardrails
- **Extend, do not rebuild.** Reuse `conftest.py`'s `admin_server` fixture and the
  fixture `network.json`. Do not introduce a parallel Playwright config or a JS test
  runner — the suite is Python pytest-playwright by design.
- **Smoke only** — render + basic interaction + no console errors + theme parity. No
  pixel snapshots, no full coverage.
- Match the existing file's assertion style and naming (`test_<thing>_<expectation>`).
- If a flow needs fixture data the current `network.json` lacks, extend the fixture
  minimally rather than mocking ad hoc.
