# 5.1 — Remove "coming soon" stubs in the Apps page · **Tier: Sonnet**

## Context
The headline Apps page ships three visible dead-ends — buttons that pop
`alert('… coming soon')` or sit disabled. A sharp reviewer clicking around hits these
immediately, and they're in the marquee feature's UI. Remove the seams: **wire the
action if a real backend exists, otherwise hide the affordance.** Never leave a stub.

## The three anchors (grep `coming soon` in `web/static/js/pages/apps.js`)
1. `Install` button → `alert('Gallery install coming soon')`.
2. `View Draft` button → `alert('Manifest viewer coming soon')`.
3. Disabled `Auto-repair (coming soon)` button — explicitly gated on the mechanical
   repair pass (`audit_runner --repair`) which has not landed.

## Task
For each, first determine whether a real endpoint exists:
- Gallery install: grep server routes for a gallery/app install endpoint
  (`grep -rn "gallery" packages/admin/evolve_admin/web/*routes*.py server.py`).
- Manifest draft viewer: grep for a manifest/draft view route.
- Auto-repair: grep for `audit_runner` `--repair` / a repair endpoint.

Then:
- **If the endpoint exists** → wire the button to it (real fetch + result handling +
  error state), matching how sibling buttons on the page call the backend.
- **If it does not exist** → remove/hide the affordance cleanly. Don't render a button
  that only alerts. For Auto-repair (known not-yet-built), hide it until the mechanical
  pass lands rather than showing a disabled teaser.

## Acceptance criteria / proof artifact
- `grep -rni "coming soon" packages/admin/evolve_admin/web/static` → **no hits**.
- Every remaining button on the Apps page does something real on click.
- Theme toggled both ways; any changed markup complies with `docs/style-guide.md`
  (width classes, no inline hex/shadows, `.expand-icon` if relevant) and
  `tools/ui-style-lint <changed-files>` passes.

## Guardrails
- **Never fake functionality.** Hiding a not-yet-built affordance is correct; stubbing it
  is not.
- Follow `docs/style-guide.md` and run `tools/ui-style-lint` on changed files.
- Verify both light and dark themes render before reporting done.
- If wiring an endpoint turns out non-trivial (more than hooking up an existing route),
  STOP — hiding is the in-scope fallback; deep new feature work is out of scope for 5.1.
