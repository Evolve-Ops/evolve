The operator is **returning to a META coordinator session** that has been idle while work ran out in chips/separate sessions, and wants one pulse that reconciles that outsourced work and drives it forward. This is the **mid-life** counterpart to `/meta` (launch/resume) and `/close` (wrap-up): launch → **pulse** → close. The authoritative procedure is the **"The return-pulse (`/status`)"** section of `docs/META-bootstrap.md` (the small, every-bout bootstrap doc; the on-demand lookups — ownership map, scheduled-automation procedures — are in the full reference `docs/META-session-guide.md`, and the Aspect registry is its own doc `docs/META-aspect-registry.md`); read it. In short:

1. **Identify the aspect** this session coordinates (from how it was launched / its in-flight ledger / its branch). If genuinely unclear, ask which `META:<id>`.

2. **Reconcile every in-flight child against artifacts — never your memory of "what's done."** Read the aspect's **structured ledger** `meta-state/<id>.json` (schema: `docs/meta-ledger-schema.md`) for the expected children, then check live state and update each chip's `bucket`/`two_pass`/`pr`/`last_commit` in place:
   - `gh pr list --repo "$(tools/meta-config)" --state all` for the aspect's `[META:<id>]` / `claude/*` PRs; classify each → `bucket`: **merged** / **open_green** / **open_red** / **draft** / **dispatched** (no-PR-yet). *(The repo slug comes from this checkout's `.claude/meta.json` via `tools/meta-config`, so the same substrate runs in any project; it falls back to `cjalden/evolve` when the file is absent. Substitute the resolved slug wherever `--repo` appears below.)*
   - A chip with no PR and no new commits for ~30 min is **stalled/dead** (the freeze signal — see the guide); set `bucket: stalled`.

3. **Auto-drive the SAFE parts** (the operator opted into auto-drive — do these without asking). The merge decision is **mechanical against the ledger fields** (`docs/meta-ledger-schema.md`): `auto-merge ⟺ bucket == open_green AND verdict_is_pass(two_pass) AND PR-body carries a pass-equivalent two-pass review section (tools/meta-verdict-check qualifies) AND reversible == true AND operator_merge != true`. `verdict_is_pass` is the **canonical verdict predicate** defined in `docs/meta-ledger-schema.md` ("The canonical verdict predicate") and implemented in `tools/meta-queue` — **NOT** an exact `== "PASS"` string match (which strands every prose verdict like `"SHIP (2 non-blocking concerns)…"`). Don't re-derive it; reference it.
   - **Auto-merge** any PR that meets that rule — first confirm the **B2 PR-body artifact** with `tools/meta-verdict-check <pr>` (exit 0 = the PR body carries an independent two-pass review section with a pass-equivalent overall verdict; the canon is `docs/meta-ledger-schema.md` "The PR-body artifact requirement"). A ledger `two_pass: PASS` with **no** such PR-body section is *self-report, not a fact* (the #3347 hole) → treat as **green-but-unverified** (auto-review below), never merge. If it qualifies, confirm checks-green by polling `gh pr checks --json name,bucket,state` (never parse text — CHECKS stay JSON; only the verdict *section* is parsed, by the helper); the chip's **pass-equivalent two-pass verdict** is part of its *done*, not a separate gate (`META-bootstrap.md`, How a META session behaves §5). Never `--auto` (this repo lacks it and it races non-required checks); poll, then merge manually. After merging, set the chip `bucket: merged`.
   - **Auto-relaunch** stalled chips from their **last pushed checkpoint** (respawn a `[META:<id>]` chip whose brief says "resume from <last commit>, push immediately") — **but first prove the chip hasn't already pushed** (spec §17 / Initiative 12, B4): "stalled" is only a ~30-min-no-commit heuristic, and a stale ledger or a truncated PR page makes it re-dispatch already-done work (the #3237 "reported awaiting but was merged" class). Before relaunching, check with **read-only JSON commands, never text-parse**: if the chip has a `branch`, `git ls-remote --heads origin <branch>` (non-empty ⇒ it pushed ⇒ don't relaunch, reconcile its real state instead); if it has a `pr`, `gh pr view <pr> --json state,mergedAt` (open or merged ⇒ never relaunch). Only relaunch a chip with **no remote branch and no open/merged PR**. Use an **untruncated** lookup when deciding whether a chip merged — if its PR isn't in the `gh pr list` page you fetched, look it up directly rather than assuming it's still awaiting.
   - **Auto-review the green-but-unverified** — a green, reversible, **non-privileged** chip whose verdict is merely missing (not pass, not blocking: `pending` / empty / `required …` / `n/a …`) **or whose ledger `two_pass` reads pass but the PR body carries no two-pass review section** (a self-reported string with no artifact behind it — `tools/meta-verdict-check` returns exit 1) is no longer parked for you: dispatch a `[META:<id>] <title> (review)` chip (bounded `review_count < 2`) whose in-chip two-pass writes the verdict to the PR body + ledger; the next pulse auto-merges on its pass. A **privileged or irreversible** unverified chip still gets a human-review poke (auditor-grade).
   - **Auto-merge is the default** — hold a green pass-equivalent PR only for a *real* reason: the reviewer returned a **blocking verdict** (`verdict_is_blocking`: FAIL / DO-NOT-MERGE / a live concern), the change is **not cheaply reversible** (could lock out access / leave the pod unrecoverable — sudoers lockout, deploy-checkout pattern, security infra with no fast rollback), or the chip is marked **`operator_merge: true`** (a reversible-but-sensitive surface the coordinator wants a human to click). Those get auditor-grade review + a human look. An ordinary, *revertible* privileged path (config/auth/appliers) that passed auditor review **auto-merges like anything else** — blocking it for a button the operator will just click is busywork. `operator_merge: true` is the explicit opt-out for the rare warranted surface; it is **valid only on a privileged or irreversible chip** — on a reversible+non-privileged one, surface it as *clearable* (don't silently override the human's flag).

4. **Confirm-first (propose, act on yes) — do NOT auto-do:** dispatching a **new** bite, **advancing to a new roadmap item**, and **closing** the session. When you surface any of these, apply **decision triage** (`META-bootstrap.md`, How a META session behaves §9): a *path-only* fork (the order of two items that both get done) you just **decide and note — don't ask**; a *product-direction* fork you escalate **with a reasoned recommendation + the 2–3 trade-offs**. Never surface a fork without a recommendation. Append every escalated product-direction fork to the ledger's `decisions_pending[]` (fork + your recommendation + reversibility) so it survives the session and feeds the operator's decision queue.

5. **Surface gaps:** a PR whose chip **skipped its in-chip two-pass review** (don't merge it, and don't spawn a *separate* review chip — bounce it back to its own chip for the reviewer pass), dropped/forgotten bites, a stale trio, unpushed commits.

6. **Keep durable state current:** write the updated **structured ledger** back to `meta-state/<id>.json` as you go (chip `bucket`/`two_pass`/`pr`/`last_commit`, refreshed `next_action`, open `gates`, `decisions_pending`; stamp `updated`), and fold durable decisions/lessons into the memory topic file + spec. A fresh `/meta <id>` reading the trio must resume exactly here.

7. **Verdict (one line):**
   - Slice still has open work → state + take/confirm the single next action.
   - Slice complete → if the roadmap has a next item, **propose advancing** to it; else report **DONE + safe-to-close** and hand to `/close`.

Keep it tight: reconcile → auto-drive the safe parts → one-line verdict + next move. It's a pulse, not a bootstrap.
